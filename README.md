# cursor-tidd

Cursor IDE 向けの**チケット駆動開発 (Ticket-Driven Development)** テンプレート。

AIアシスタントとの会話を構造化されたチケットに整理し、作業コンテキストを保持しながら開発を進めるためのフレームワークです。

## TiDD とは

TiDD (Ticket-Driven Development) は、すべての作業をチケットとして管理する開発スタイルです。cursor-tidd では以下の特徴を持ちます：

- **1チケット = 1ファイル**: `_tickets/<NNN>-<slug>.ticket.md` にすべてを集約
- **作業ログが主役**: 調査結果・手順・判明した事実を時系列で蓄積し、日を跨いでもコンテキストを失わない
- **AIフレンドリー**: Cursor のスラッシュコマンドと連携し、会話から自然にチケットを生成
- **軽量**: 最小限のルールで最大限の効果。プロジェクトに合わせて柔軟にカスタマイズ可能

## クイックスタート

### 1. テンプレートをコピー

自分のプロジェクトに以下のディレクトリをコピーしてください：

```
.cursor/
├── rule/
│   └── tidd.mdc              # 基本ルール（alwaysApply: true）
├── commands/
│   ├── ticket.md              # /ticket コマンド
│   └── implement.md           # /implement コマンド
├── template/
│   └── slug.ticket.md         # チケットテンプレート
└── steering/
    └── steering.md            # プロジェクトメモリ（テンプレート）

_tickets/                      # チケット格納ディレクトリ（空で作成）
```

### 2. steering.md をカスタマイズ

`.cursor/steering/steering.md` を自分のプロジェクトに合わせて編集します。プロジェクト概要・技術スタック・制約条件を記載してください。

### 3. 開発を始める

Cursor IDE で会話しながら、やることが見えてきたら `/ticket` で整理し、`/implement` で実装を進めます。

## ワークフロー

```
1. 自然な会話でアイデアを話す
   ↓
2. /ticket でチケットに整理
   ↓
3. /ticket でタスク分解
   ↓
4. /implement を確認しながら実装
   ↓
5. 重要な決定は steering.md に記録
```

## コマンド一覧

| コマンド | 用途 | タイミング |
|----------|------|-----------|
| `/ticket` | 会話内容をチケットに整理・タスク分解 | やることが見えてきたら |
| `/implement` | タスク実装とチケット更新 | 実装開始時 |

## チケットの構成

```markdown
# タイトル

**Status**: draft | **Created**: YYYY-MM-DD

---

## 背景と目的        ← なぜこの作業が必要か
## 方針              ← どう解決するか
## タスク一覧        ← 何をやるか（実行可能なタスク）
## 作業ログ          ← 時系列の記録
## 参考URL           ← 末尾
```

## ドキュメントの役割分担

| ファイル | 役割 | 内容 |
|---------|------|------|
| `README.md` | プロジェクト紹介 | 外部向けの概要、セットアップ手順 |
| `.cursor/steering/steering.md` | 意思決定の記録 | なぜこうなったか、選択の背景と理由 |
| `_tickets/<slug>.ticket.md` | チケット単位の作業記録 | 背景・方針・タスク・作業ログ・参考URL |

## カスタマイズ

### プロジェクト固有のルールを追加

`.cursor/rule/tidd.mdc` の末尾にプロジェクト固有のルール（破壊的コマンドの制限など）を追加できます。

### チケットテンプレートの拡張

`.cursor/template/slug.ticket.md` を編集して、プロジェクトに必要なセクションを追加できます。
