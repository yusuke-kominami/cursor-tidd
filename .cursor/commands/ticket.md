# チケットの作成

ここまでの会話内容をチケットとして整理し、`_tickets/` 配下にディレクトリとファイルを作成します。

## ステップ 1: 内容を整理

会話の内容をもとに、`.cursor/template/split/` のテンプレートを参考にチケットを作成してください。

**`{NNN}-ticket.md`**（必須）:

```markdown
# [タイトル]

**Status**: draft | **Created**: YYYY-MM-DD

**関連ファイル**:
- [作業ログ](./NNN-worklog.md)

---

## 背景と目的
- なぜこの作業が必要か
- 何を解決 / 実現したいか

## 方針
- どういうアプローチで進めるか
- 現時点でわかっていること / わかっていないこと

## タスク一覧

| # | タスク | 状態 |
|---|--------|------|

## 参考URL
- 
```

**`{NNN}-worklog.md`**（必須）:

```markdown
# NNN 作業ログ — [タイトル]

> [メインチケット](./NNN-ticket.md)

---

<!-- 時系列で追記していく（新しい作業を上に追加）。調査結果、判明した事実、決定事項、手順の調査結果などを含む -->
```

## ステップ 2: ディレクトリ名を決定

```
_tickets/<NNN>-<slug>/
```

- `NNN`: 3桁の連番プレフィックス（既存チケットの最大番号 + 1）
- `slug`: 内容を英語ケバブケースで（例: `fix-athena-timeout`, `setup-glue-job`）

既存の `_tickets/` を確認し、最大番号と重複がないか確認すること。

## ステップ 3: ファイルを作成

ユーザーが確認したら以下を作成してください：

1. ディレクトリ `_tickets/<NNN>-<slug>/` を作成
2. `<NNN>-ticket.md` を作成（必須）
3. `<NNN>-worklog.md` を作成（必須）
4. 必要に応じて `<NNN>-pr.md`、`<NNN>-deployments.md` を作成

テンプレート内の `NNN` を実際の番号に置換すること。

## 原則

- `.cursor/steering/steering.md` を参照し、既存の技術スタックや制約と整合性を取る
- 「方針」は現時点でわかる範囲でよい。調査系なら「まず〇〇を確認する」程度で十分
- タスク一覧は空でもよい（後からタスク分解で埋める）
- 作業ログは `{NNN}-worklog.md` に会話の中で判明したことを逐次追記していく
- `{NNN}-pr.md` と `{NNN}-deployments.md` はプロジェクトの性質に応じて必要なもののみ作成する

## ステップ 4: タスク分解

チケット作成後、続けてタスク分解まで行う。

### タスク生成

「背景と目的」「方針」の内容をもとに、以下のフォーマットでタスク一覧セクションに書き込む：

```markdown
| # | タスク | 状態 |
|---|--------|------|
| 1 | タスク名 | ⬜ 未着手 |
| 2 | タスク名 | ⬜ 未着手 |
| 3 | タスク名 | ⬜ 未着手 |
```

### タスク分解の原則

- **粒度**: 3時間以内で完了できるサイズ
- **WHATで書く**: 「何を実現するか」を書く。ファイル名や関数名は書かない
- **方針の全体をカバー**: 方針セクションの内容がすべてタスクに紐づいていること

### チケットファイルを更新

- タスク一覧セクションに書き込む
- Status を `draft` → `in-progress` に更新

## 作成後の案内

「`_tickets/<NNN>-<slug>/` を作成しました。タスク1から進めますか？」
